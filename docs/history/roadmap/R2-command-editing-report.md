## 1. 怎么用（一次组合修改）

已有课程目录，要：新增一个按名称搜索的输入、新增使用它的查询能力、把旧能力 `UpdateCourse` 的第一个校验条件放宽。三条指令放进同一批：

```text
Add     声明集合 ← 新输入 SearchByNameInput
Add     声明集合 ← 新能力 SearchCoursesByName（引用上面的输入）
Update  UpdateCourse.workflow.steps[0].condition ← 新条件
```

结果是一份完整的新 SIR 文本和两份预览：软件层面"变了什么"（两项新增、一项更新）、文本层面"哪些声明被重写／插入"。中间状态（只有输入、没有能力）不会落盘；任何一条失败，整批都不产生结果。换成商品／订单的同类修改，指令种类完全相同。

## 2. 新增了什么，以及为什么存在

| 部件 | 位置 | 为什么存在 |
| --- | --- | --- |
| `SoftwareDraft` 与 `DraftValidator` | `sir-semantic/.../schema` | 编辑需要一份"只含作者写下的内容"的副本：引用用名字而不是已解析的 id（新增节点还没有 id，写回源码时也只能写名字）。校验只管形状（种类允许、必填槽在、数值可解析），含义留给正式分析 |
| `SirDeclarationWriter` | `sir-semantic/.../source` | 唯一知道"草稿节点在语言里怎么写"的地方：六种声明、七种步骤、带优先级的表达式、类型、约束、`@id`。语言写不出的内容（例如含控制字符的字符串）直接拒绝，不写"看起来像"的替代品 |
| `CommentScanner` | `sir-parser` | 解析器把注释丢掉，但改写文件的工具必须知道会碰到哪些注释。它用同一个词法器读出每条注释的位置 |
| `Command`（Add／Delete／Update）、`Selector`、`CommandBatch` | `sir-change/.../edit` | 固定三种机械操作。选择器是槽位路径，集合元素按名字或序号选，不按相似度猜。批绑定协议版本、软件名和源文本的 SHA-256，源变了就是陈旧，直接拒绝 |
| `DraftEdit` | 同上 | 按选择器找槽位、检查新值形状、替换子树；已有名字不覆盖、身份不可编辑、替换保留原身份、可选的"预期旧值"防止改到过期目标 |
| `SemanticDelta` | 同上 | 沿 schema 对比两份草稿，报告软件变了什么；有身份或名字的元素按它匹配，在中间插入一个字段只算一次新增 |
| `SourceEditor` | 同上 | 把以上串起来：读源码 → 草稿 → 执行指令 → **只重写改动的声明** → 对结果**重新跑一遍完整的正式分析** → 核对它读回来正好是指令产生的草稿，才返回 |

## 4. 与计划相比的调整（有限优化）

1. **写出器放在语义层**，不是计划里的"解析层打印 AST、语义层转 AST"两段。原因：草稿已是语义节点，再造一层 AST 要写两遍同样的逐种类映射；回读核验已经覆盖了它的正确性。代价：语法知识放在了 `sir-semantic`，由 `SirDeclarationWriter` 一处承载。
2. **草稿里引用用名字**，批内句柄不需要：后面的指令直接用名字引用前面新增的节点即可。
3. **`fails`、`requires` 改为无序集合**（`@Keyed` 允许纯值集合）：语言本身会排序去重，当作有序列表会让合法编辑被误判为不一致。写出器按语言要求的顺序输出。
4. **能力的 `input`／`actor` 引用写的是变量的类型名**，所以 `@Reference` 增加 `viaVariableType` 开关，而不是在代码里写特例。
5. **R1 的一批字段改归"派生"**（解析结果而非作者写的内容），详见 R1 报告第 6 节。
6. **新增声明一律追加在最后一个保留声明之后**；声明按身份匹配，没有"位置"的语义，所以 `position` 对它们被忽略。

## 5. 当前明确不支持（会给出原因并拒绝，不会写出半成品）

| 场景 | 拒绝原因 |
| --- | --- |
| 修改软件名、metadata、target | `NOT_SUPPORTED_YET` |
| 多文件（0.2）工程 | 解析入口不接受，属 R3 之后 |
| 以 BOM 开头的源 | `UNSUPPORTED_SOURCE` |
| 重写或删除**含注释**的声明 | `PROTECTED_COMMENT`，指出行号和声明名。声明之外、声明之间的注释都保留 |
| 新增声明时携带 `@id`（持久身份） | 身份只来自已有声明；新声明不带 id |
| 文件里没有任何保留声明时新增 | 没有插入锚点 |
| 同一行有两个被改的声明 | 文本区间重叠 |
| 改名跨引用传播 | 不做：删除或改名后别处仍引用，交给正式分析报错 |
