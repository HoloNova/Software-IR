# 选题试写：用 SIR 写八个典型后端，看语言还缺什么（2026-10-21）

## 1. 做了什么，为什么

[设计 12](../design/12-feature-semantics-and-semantic-types.md) 之后语言已经能写不少东西，但"够不够"一直靠猜。这次的做法：选八个毕设、课程设计或小团队常见的后端题目，每题先列真实需求，再用 SIR 逐条写；写不出来的记下来，不绕开、不修语言。每份源码放在 `sir-toolchain-application/src/test/resources/topics/<题目>/project.sir`，由 `TopicSamplesTest` 保证它们一直是合法、能生成、能交付的软件。

原版源码经过三道检查：SIR 分析与生成、交付规划（`kcg package` 那一步）、生成出的 Java 工程用 Maven 离线编译（`TopicSamplesOfflineCompilationTest`，CI 里逐个编译，原版在本机跑过一遍）。G10 后 market／shop／ledger 已从整数分改为 Money；G6 又补了 shop 的单商品多件数量与金额乘法。`997794c` 的 #147 已通过三道检查，生成工程离线编译证据见[验证第19节](README.md#ci-147-accepted)。没有起 MySQL 跑这八题的 HTTP 业务，不能把“表达出来”视为业务行为已验证。

**一句话结论：**84 条需求里，**78 条完整写出、6 条带折扣、0 条尚未写出（92.9%／7.1%／0%）**。图书可借数量和逾期罚款已由 #178 在真实 MySQL 上验收。带折扣的六条都已实现（记账的图表与导出只有图表所需的数，导出文件属于不做的 G14）、定向回归通过，等同源码 CI 验收：商城的优惠券、下单、一个订单多个商品和购物车（G5 第二片，见[设计 31](../design/12-feature-semantics-and-semantic-types.md)），以及会议室的每周重复预约（`repeat` 与 `addDays`，[设计 32](../design/12-feature-semantics-and-semantic-types.md)）。第一版只有 58% 完整写出；之后补上的并发计数、联合唯一、可选值、存在与计数、金额、乘法、计算视图、求和与分组、有界遍历、跨行计数，都是同一提交的 CI 在真实 MySQL 上验收通过后才计为完整。普通的增删改查、分页、登录归属和状态流转，大约 150 到 450 行 SIR 就能写完。

**接手验收（2026-10-25）：**已拉取`fc60661`并核对业务源码`0ac9739`的#183。Frozen通过；乘法／商城真实检查182通过、仅“无诊断”断言因非阻断警告失败，购物车／每周预约回滚与优惠券并发检查均已执行；Money326项全通过且包含avg。原始XML唯一失败与资源哈希已独立核对，见[验证49](README.md#ci-183-compilation-warning-fix)。验收器修复后9类65项定向通过；独立验证／CLI／部署在#183均跳过，当前账本保持78／6／0，不提前升级。图表所需的数不等于已实现文件导出，G14折扣继续保留。

## 3. 各题的需求与结果

记号：✓ 写出；✗ 尚未写出，后面是缺口或待补业务编号（第 4 节）；△ 写出但有折扣，说明在括号里。

**校园二手交易（market）**
✓ 注册登录；✓ 卖家发布、改、删自己的商品（Crud）；✓ 卖家更新的系统字段保护（G9：状态和创建时间不在输入里，卖家归属来自登录；#172 真库逐题验收）；✓ 按关键字浏览在售商品（D5 已修，#173 真库验收）；✓ 商品详情；✓ 购买（并发下只有一人买到，用守卫更新）；✓ 不能买自己的；✓ 我的订单；✓ 卖家看卖出的订单（下单时把卖家抄到订单上）；✓ 取消订单并重新上架；✓ 订单里显示商品信息；✓ 按价格区间、成色等可选条件筛选（显式空值判断与比较组合，G7；D5 已修，#173 真库验收）。

**图书借阅（library）**
✓ 注册、读者与馆员两种角色；✓ 馆员添加副本、按条码借书（副本状态守卫，并发只有一人借到）；✓ 书名或作者检索；✓ 续借一次；✓ 我的在借；✓ 馆员看逾期；✓ 还书；✓ 馆员维护图书目录（G9：只有馆员能写，目录公开可读；#172 真库逐题验收）；✓ 每人最多借5本（#168实际题目的并发最后名额、借还一致性和回滚验收）；✓ 书目显示可借数量（count 视图与 Crud readView；#178 同 SHA 真库验收详情与分页的读取预算和计数）；✓ 逾期罚款 = 天数 × 费率（`daysBetween` 与 `max`，还书时按逾期整天数罚 0.50／天、提前还不罚，[设计第 30 节](../design/12-feature-semantics-and-semantic-types.md#built-in-functions)；#178 同 SHA 真库验收：73 小时后还得 1.50、未逾期为 0）；✓ 预约已借出的书（#168验收严格FIFO、本人扫码领取、取消、共同Book锁和并发回滚；不是还书自动分配）。

**在线选课（course）**
✓ 管理员建课；✓ 搜索课程；✓ 我的选课；✓ 教师看自己课程的名单；✓ 选课（一条语句检查名额并加一，并发不超卖）；✓ 退课（座位数由数据库减一）；✓ 不能重复选同一门（联合唯一）；✓ 时间冲突检测（#168真库并发及先等学生锁后重查冲突通过）；✓ 显示剩余名额；✓ 先修课检查（#168验收任意直接先修集合、可信通过记录及发布冻结；不是递归闭包）。

**校园博客（blog）**
✓ 注册；✓ 作者管理自己的文章（Crud）；✓ 草稿发布（守卫更新）；✓ 公开列表与搜索；✓ 按分类看文章；✓ 评论分页；✓ 删除自己的评论；✓ 分类管理；✓ 文章关联多个标签、按选中的标签看文章（G4；不是动态标签列表的交集查询）；✓ 文章页同时带出评论；✓ 每人只能点一次赞（联合唯一）；✓ 点赞数并发不丢（由数据库加一）。

**任务看板（tasks）**
✓ 项目增删改查（Crud）；✓ 项目所有者建任务；✓ 指派；✓ 被指派人改状态；✓ 项目任务按状态分页；✓ 我的任务；✓ 逾期任务（到期时间可空，空值不算逾期）；✓ 项目成员也能看和改任务（所有者授予成员资格，exists 组合授权，G2）；✓ 未指派的任务（项目所有者或成员读取）；✓ 多条件可选筛选（状态、优先级）。

**网上商城（shop）**
✓ 管理员加商品；✓ 搜索在售商品；✓ 支付（守卫更新）；✓ 发货；✓ 我的订单；✓ 订单明细；△ 下单（同一种商品可一次买多件，库存由一条语句检查并减数量，#147通用并发购买已验证；多商品经购物车结账，待同源码 CI）；✓ 取消订单（#171实际shop组合真库验收：有界返库、重复取消／Pay竞争、父锁等待、100／101条、非严格上限及晚失败整笔回滚通过）；△ 一个订单多个商品（购物车结账：逐项锁商品扣库存、写明细、订单总额由数据库累加，售罄整笔回滚；接在乘法业务 IT，待同源码 CI）；✓ 金额 = 单价 × 数量（#147 同SHA生成工程、真实精确金额、并发数量及精度失败回滚通过）；△ 购物车（加入、改数量、移除、查看、清空，同一商品一行；待同源码 CI）；△ 优惠券（需求由实现者定义：立减、有效期、起用金额、总次数、一人一张、一单一券、取消退券，只用已有能力组合，见[设计 33](../design/12-feature-semantics-and-semantic-types.md)；待同源码 CI）。

**会议室预约（booking）**
✓ 管理员加房间；✓ 房间列表；✓ 预约；✓ 取消预约；✓ 我的预约；✓ 房间日程；✓ 不能与已有预约重叠（半开区间、Room 锁与后置检查；#154 的 72 项乘法／预约报告含 8 并发恰一成功和真实先读后等锁屏障）；△ 每周重复预约（`repeat` 重复若干周，每周检查冲突并写入，一周被占整个系列回滚；接在乘法业务 IT，待同源码 CI）。该项只依据 #154 的实际真库证据升级，不从内存编译推导真库通过。

**个人记账（ledger）**
✓ 分类管理（Crud）；✓ 记账增删改查（Crud）；✓ 按时间区间看账目；✓ 按分类和区间看账目；✓ 预算的增删改查；✓ 月度每类合计（#170：本人保存时区＋自然月，真实微秒月界、非UTC绑定及偏好快照通过）；✓ 预算超支提示（#170：指定本人预算及分类、当前规则精确比较，等额不超且规则变更影响历史重查；不做每期历史预算）；△ 图表数据、导出（图表要的数——区间合计、按分类合计、月度每类合计、预算超支、区间平均和按分类平均（`avg`，[设计 34](../design/12-feature-semantics-and-semantic-types.md)）——接口都有，客户端逐月调用即可画图；导出文件属于 G14，不做；平均值待同源码 CI）。

## 5. 缺陷（语言检查放过，生成的 Java 编不过或结果不对）

写第一版时，八个题目里有六个生成出来的 Java 编译失败，原因是下面这几处。它们比"写不出"更糟，因为 SIR 这一关是绿的。第一版为了拿到能编译的样例，绕开了它们。**现在都已修好（见表后）。**

| 编号 | 现象 | 例子 | 方向 |
| --- | --- | --- | --- |
| D1 | `load 实体 by 行.引用.id` 通过检查，生成 `行.getXxxId().getId()`，对 `Long` 取 `getId()`，编译失败；而 `load 实体 by 行.引用` 因为类型对不上被拒绝。所以**没有任何办法顺着引用加载目标行** | 取消订单要重新加载商品、还书要加载副本、退课要加载课程、指派任务要加载项目 | 让 `load` 接受同一实体的引用值（最小改动） |
| D2 | 视图里嵌套另一个视图（如订单视图里放商品视图），在 `find` 分页读里可用，但从 `load`、`create` 之后 `return` 出来时，生成的构造器传的是编号而不是视图，编译失败 | 市场、图书、选课、博客、任务、预约六题的第一版都踩到 | 要么在这些路径上补读关联行，要么在语义检查时就拒绝 |
| D3 | 把可选的请求参数直接和字段比较（`item.kind == input.kind`），生成 `eq(列, input.getKind())`；参数为空时变成与空值比较，查不到任何行，没有错误 | 可选筛选条件 | 语义检查拒绝，或生成"为空则不加条件" |
| D4 | 视图里写子行列表（`field comments: List<CommentView>`）并从 `load` 返回，生成 `p.getPostId()`，编译失败（只有 `find` 分页读支持这种视图） | 文章详情带评论 | 同 D2 |
| D5 | 表名或列名是 MySQL 保留字时，工作流里手工拼接的 SQL 片段没有加反引号，在真实 MySQL 上是语法错误。语言检查、生成和离线编译都通过 | 二手交易的商品浏览按 `condition`（成色）筛选，生成 `COALESCE(condition = ?, FALSE)`；这段条件不管请求带不带成色都会拼进去，所以这个接口每次调用都失败 | 所有写进 SQL 文本的表名、列名走同一个加引号规则 |

**D1 到 D4 已修（2026-10-20）：**
- D1：`load 实体 by 行.引用` 现在合法（引用里存的就是被引用行的主键），`行.引用.id` 生成的 Java 也不再多调一次 `getId()`。
- D2、D4：`load` 或 `create` 之后 `return` 的那一行，现在可以带嵌套的视图，一对一和一对多都行。做法和分页 `find` 一样，每个嵌套多一条批量查询（返回步骤在中间表示里声明条数，校验时核对）。一对多读出全部子行，不分页。
- D3：最初在 `find` 谓词里拒绝可选值比较以免猜含义；G7 已以明确的空值规则替代拒绝：普通比较遇空为 false，需要跳过条件就显式写空值判断，不静默跳过。

**D5 已修（2026-10-24，`00b8118`），#173 真库验收：**实体映射注解在此之前已经给保留字加了引号（`91fc78e`），但工作流里另有几处 SQL 是直接拼名字的：可选值比较、同一行两列比较、字面匹配、`exists`／`any` 的关联子查询，以及带版本号实体的加锁读取和条件更新。现在它们和映射注解共用一份 MySQL 8.4 保留字表（`MySqlIdentifiers`），保留字加反引号，普通名字的生成结果一个字节都不变。`ReservedIdentifierRuntimeTest` 用全是保留字的表名、列名，从真实生成的服务和 Mapper 里取出 MyBatis 实际发出的 SQL 检查；去掉加引号后三项全部失败。真库这一侧，图书借阅的业务验收原本就组合了二手交易的 `Item`，现在把浏览接口也组合进去，按成色筛选有、无、匹配、不匹配四种情况都在真实 MySQL 上请求一次；[#173](https://github.com/HoloNova/Software-IR/actions/runs/40091408584) 中这四项和图书借阅的其余检查（共 255 项）全部通过。这次只是按保留字补引号，没有改变"按 MySQL 8.4 的保留字表"这个范围。

题目样例里为绕开 D1、D2 而多传的参数、改成编号的视图字段都已还原成自然写法（订单里带商品、课程里带教师、文章页带评论列表），八个题目生成的工程由 `TopicSamplesOfflineCompilationTest` 在 CI 里逐个离线编译；旧版在本机跑过一遍并通过；当前G6／G10更新版已由 `997794c` 的 #147 完成八题离线编译；其后源码仍须新的同SHA证据。
