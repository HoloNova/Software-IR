# 选题试写：用 SIR 写八个典型后端，看语言还缺什么（2026-10-21）

## 1. 做了什么，为什么

[设计 12](../design/12-feature-semantics-and-semantic-types.md) 之后语言已经能写不少东西，但"够不够"一直靠猜。这次的做法：选八个毕设、课程设计或小团队常见的后端题目，每题先列真实需求，再用 SIR 逐条写；写不出来的记下来，不绕开、不修语言。每份源码放在 `sir-toolchain-application/src/test/resources/topics/<题目>/project.sir`，由 `TopicSamplesTest` 保证它们一直是合法、能生成、能交付的软件。

原版源码经过三道检查：SIR 分析与生成、交付规划（`kcg package` 那一步）、生成出的 Java 工程用 Maven 离线编译（`TopicSamplesOfflineCompilationTest`，CI 里逐个编译，原版在本机跑过一遍）。G10 后 market／shop／ledger 已从整数分改为 Money；G6 又补了 shop 的单商品多件数量与金额乘法。`997794c` 的 #147 已通过三道检查，生成工程离线编译证据见[验证第19节](README.md#ci-147-accepted)。首次试写没有起 MySQL 跑这八题的 HTTP 业务。后续关键业务接入已有组合IT，当前证据见[验证50](README.md#ci-184-accepted)；仍不能把八题离线编译说成八个独立应用逐题HTTP验收。

**一句话结论：**84条需求里，**83条完整写出、1条带折扣、0条尚未写出（98.8%／1.2%／0%）**。`5972072`的#184已完成Frozen、业务IT、独立验证、CLI和冷部署验收：商城下单、多商品订单、购物车、优惠券及每周重复预约五条由△转✓。图书可借数量与逾期罚款、记账平均值等也在同SHA回归通过。唯一折扣是记账的合并需求“图表数据、导出”：图表所需的数已由接口提供，文件导出属于不做的G14，不能整条计✓。第一版只有58%完整写出；关键业务仍以同源码真实MySQL证据验收，不把生成通过当成行为正确。

**最新验收（2026-10-25）：**[verify #184](https://github.com/HoloNova/Software-IR/actions/runs/40155600764)，SHA `5972072eb920e5c21ea8d2ac5c4f88ecd98ef66c`。284份上传XML共1970项，0失败／错误／跳过（含随后IT，不冒称单次Frozen计数）；乘法／商城183、Money326、library299、course151等全部通过，13份业务报告的SIR／DDL／seed哈希与当前资源一致。部署报告同SHA，98个HTTP请求符合预期，既有正／负独立验证也按约定通过。#183的原失败和修复过程保留在[验证49](README.md#ci-183-compilation-warning-fix)，完整证据见[验证50](README.md#ci-184-accepted)。

## 5. 缺陷（语言检查放过，生成的 Java 编不过或结果不对）

写第一版时，八个题目里有六个生成出来的 Java 编译失败，原因是下面这几处。它们比"写不出"更糟，因为 SIR 这一关是绿的。第一版为了拿到能编译的样例，绕开了它们。**现在都已修好（见表后）。**

| 编号 | 现象 | 例子 | 方向 |
| --- | --- | --- | --- |
| D1 | `load 实体 by 行.引用.id` 通过检查，生成 `行.getXxxId().getId()`，对 `Long` 取 `getId()`，编译失败；而 `load 实体 by 行.引用` 因为类型对不上被拒绝。所以**没有任何办法顺着引用加载目标行** | 取消订单要重新加载商品、还书要加载副本、退课要加载课程、指派任务要加载项目 | 让 `load` 接受同一实体的引用值（最小改动） |
| D2 | 视图里嵌套另一个视图（如订单视图里放商品视图），在 `find` 分页读里可用，但从 `load`、`create` 之后 `return` 出来时，生成的构造器传的是编号而不是视图，编译失败 | 市场、图书、选课、博客、任务、预约六题的第一版都踩到 | 要么在这些路径上补读关联行，要么在语义检查时就拒绝 |
| D3 | 把可选的请求参数直接和字段比较（`item.kind == input.kind`），生成 `eq(列, input.getKind())`；参数为空时变成与空值比较，查不到任何行，没有错误 | 可选筛选条件 | 语义检查拒绝，或生成"为空则不加条件" |
| D4 | 视图里写子行列表（`field comments: List<CommentView>`）并从 `load` 返回，生成 `p.getPostId()`，编译失败（只有 `find` 分页读支持这种视图） | 文章详情带评论 | 同 D2 |
| D5 | 表名或列名是 MySQL 保留字时，工作流里手工拼接的 SQL 片段没有加反引号，在真实 MySQL 上是语法错误。语言检查、生成和离线编译都通过 | 二手交易的商品浏览按 `condition`（成色）筛选，生成 `COALESCE(condition = ?, FALSE)`；这段条件不管请求带不带成色都会拼进去，所以这个接口每次调用都失败 | 所有写进 SQL 文本的表名、列名走同一个加引号规则 |

**D1 到 D4 已修（2026-10-20）：**
- D1：`load 实体 by 行.引用` 现在合法（引用里存的就是被引用行的主键），`行.引用.id` 生成的 Java 也不再多调一次 `getId()`。
- D2、D4：`load` 或 `create` 之后 `return` 的那一行，现在可以带嵌套的视图，一对一和一对多都行。做法和分页 `find` 一样，每个嵌套多一条批量查询（返回步骤在中间表示里声明条数，校验时核对）。一对多读出全部子行，不分页。
- D3：最初在 `find` 谓词里拒绝可选值比较以免猜含义；G7 已以明确的空值规则替代拒绝：普通比较遇空为 false，需要跳过条件就显式写空值判断，不静默跳过。

**D5 已修（2026-10-24，`00b8118`），#173 真库验收：**实体映射注解在此之前已经给保留字加了引号（`91fc78e`），但工作流里另有几处 SQL 是直接拼名字的：可选值比较、同一行两列比较、字面匹配、`exists`／`any` 的关联子查询，以及带版本号实体的加锁读取和条件更新。现在它们和映射注解共用一份 MySQL 8.4 保留字表（`MySqlIdentifiers`），保留字加反引号，普通名字的生成结果一个字节都不变。`ReservedIdentifierRuntimeTest` 用全是保留字的表名、列名，从真实生成的服务和 Mapper 里取出 MyBatis 实际发出的 SQL 检查；去掉加引号后三项全部失败。真库这一侧，图书借阅的业务验收原本就组合了二手交易的 `Item`，现在把浏览接口也组合进去，按成色筛选有、无、匹配、不匹配四种情况都在真实 MySQL 上请求一次；[#173](https://github.com/HoloNova/Software-IR/actions/runs/40091408584) 中这四项和图书借阅的其余检查（共 255 项）全部通过。这次只是按保留字补引号，没有改变"按 MySQL 8.4 的保留字表"这个范围。

题目样例里为绕开 D1、D2 而多传的参数、改成编号的视图字段都已还原成自然写法（订单里带商品、课程里带教师、文章页带评论列表），八个题目生成的工程由 `TopicSamplesOfflineCompilationTest` 在 CI 里逐个离线编译；旧版在本机跑过一遍并通过；当前G6／G10更新版已由 `997794c` 的 #147 完成八题离线编译；其后源码仍须新的同SHA证据。
