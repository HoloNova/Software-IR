# 选题试写：用 SIR 写八个典型后端，看语言还缺什么（2026-10-21）

## 1. 做了什么，为什么

[设计 12](../design/12-feature-semantics-and-semantic-types.md) 之后语言已经能写不少东西，但"够不够"一直靠猜。这次的做法：选八个毕设、课程设计或小团队常见的后端题目，每题先列真实需求，再用 SIR 逐条写；写不出来的记下来，不绕开、不修语言。每份源码放在 `sir-toolchain-application/src/test/resources/topics/<题目>/project.sir`，由 `TopicSamplesTest` 保证它们一直是合法、能生成、能交付的软件。

原版源码经过三道检查：SIR 分析与生成、交付规划（`kcg package` 那一步）、生成出的 Java 工程用 Maven 离线编译（`TopicSamplesOfflineCompilationTest`，CI 里逐个编译，原版在本机跑过一遍）。G10 后 market／shop／ledger 已从整数分改为 Money；G6 又补了 shop 的单商品多件数量与金额乘法。`997794c` 的 #147 已通过三道检查，生成工程离线编译证据见[验证第19节](README.md#ci-147-accepted)。没有起 MySQL 跑这八题的 HTTP 业务，不能把“表达出来”视为业务行为已验证。

**一句话结论：**84条需求里，**74条完整、3条带折扣、7条尚未写出（88.1%／3.6%／8.3%）**。#168的同SHA真库与完整部署证据把借阅限额、FIFO本人领取、课程冲突和任意直接先修四项从△转✓，不是新写四项需求。历史上第一版为58%完整，补并发、查询、金额和计算视图后曾到67／8／9；当前不再沿用这个待验收数字。普通增删改查、分页、登录归属和状态流转可用约150至450行SIR表达；未写出项主要是列表／批量、跨行数量、日期差和图表／导出；自然月及当前预算已由#170同SHA真库／部署验收，两项转完整；#171又将取消订单返库转完整。分组统计本身已由#168验收，不能继续把它列成没有实现的能力。

## 3. 各题的需求与结果

记号：✓ 写出；✗ 尚未写出，后面是缺口或待补业务编号（第 4 节）；△ 写出但有折扣，说明在括号里。

**校园二手交易（market）**
✓ 注册登录；✓ 卖家发布、改、删自己的商品（Crud）；△ 卖家更新的系统字段保护（G9本批已补实际题目执行、HTTP／数据库验收与Optional修复，14类127项通过；新同SHA真库待CI，不凭旧通用IT转完整）；✓ 按关键字浏览在售商品；✓ 商品详情；✓ 购买（并发下只有一人买到，用守卫更新）；✓ 不能买自己的；✓ 我的订单；✓ 卖家看卖出的订单（下单时把卖家抄到订单上）；✓ 取消订单并重新上架；✓ 订单里显示商品信息；✓ 按价格区间、成色等可选条件筛选（显式空值判断与比较组合，G7）。

**图书借阅（library）**
✓ 注册、读者与馆员两种角色；✓ 馆员添加副本、按条码借书（副本状态守卫，并发只有一人借到）；✓ 书名或作者检索；✓ 续借一次；✓ 我的在借；✓ 馆员看逾期；✓ 还书；△ 馆员维护图书目录（G9逐题馆员／读者、公开读及Optional出版社已验证并接入原IT；新同SHA真库待CI）；✓ 每人最多借5本（#168实际题目的并发最后名额、借还一致性和回滚验收）；✗ 书目显示可借数量（G8、G11）；✗ 逾期罚款 = 天数 × 费率（乘法已补，仍缺日期差／逾期天数计算）；✓ 预约已借出的书（#168验收严格FIFO、本人扫码领取、取消、共同Book锁和并发回滚；不是还书自动分配）。

**在线选课（course）**
✓ 管理员建课；✓ 搜索课程；✓ 我的选课；✓ 教师看自己课程的名单；✓ 选课（一条语句检查名额并加一，并发不超卖）；✓ 退课（座位数由数据库减一）；✓ 不能重复选同一门（联合唯一）；✓ 时间冲突检测（#168真库并发及先等学生锁后重查冲突通过）；✓ 显示剩余名额；✓ 先修课检查（#168验收任意直接先修集合、可信通过记录及发布冻结；不是递归闭包）。

**校园博客（blog）**
✓ 注册；✓ 作者管理自己的文章（Crud）；✓ 草稿发布（守卫更新）；✓ 公开列表与搜索；✓ 按分类看文章；✓ 评论分页；✓ 删除自己的评论；✓ 分类管理；✓ 文章关联多个标签、按选中的标签看文章（G4；不是动态标签列表的交集查询）；✓ 文章页同时带出评论；✓ 每人只能点一次赞（联合唯一）；✓ 点赞数并发不丢（由数据库加一）。

**任务看板（tasks）**

**个人记账（ledger）**
✓ 分类管理（Crud）；✓ 记账增删改查（Crud）；✓ 按时间区间看账目；✓ 按分类和区间看账目；✓ 预算的增删改查；✓ 月度每类合计（#170：本人保存时区＋自然月，真实微秒月界、非UTC绑定及偏好快照通过）；✓ 预算超支提示（#170：指定本人预算及分类、当前规则精确比较，等额不超且规则变更影响历史重查；不做每期历史预算）；✗ 图表数据、导出（G8、G14）。

## 5. 缺陷（语言检查放过，生成的 Java 编不过或结果不对）

写第一版时，八个题目里有六个生成出来的 Java 编译失败，原因是下面这几处。它们比"写不出"更糟，因为 SIR 这一关是绿的。第一版为了拿到能编译的样例，绕开了它们。**现在都已修好（见表后）。**

| 编号 | 现象 | 例子 | 方向 |
| --- | --- | --- | --- |
| D1 | `load 实体 by 行.引用.id` 通过检查，生成 `行.getXxxId().getId()`，对 `Long` 取 `getId()`，编译失败；而 `load 实体 by 行.引用` 因为类型对不上被拒绝。所以**没有任何办法顺着引用加载目标行** | 取消订单要重新加载商品、还书要加载副本、退课要加载课程、指派任务要加载项目 | 让 `load` 接受同一实体的引用值（最小改动） |
