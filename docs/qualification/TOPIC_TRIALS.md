# 选题试写：用 SIR 写八个典型后端，看语言还缺什么（2026-10-20）

## 1. 做了什么，为什么

[设计 12](../design/12-feature-semantics-and-semantic-types.md) 之后语言已经能写不少东西，但"够不够"一直靠猜。这次的做法：选八个毕设、课程设计或小团队常见的后端题目，每题先列真实需求，再用 SIR 逐条写；写不出来的记下来，不绕开、不修语言。每份源码放在 `sir-toolchain-application/src/test/resources/topics/<题目>/project.sir`，由 `TopicSamplesTest` 保证它们一直是合法、能生成、能交付的软件。

每份源码都经过三道检查：SIR 分析与生成、交付规划（`kcg package` 那一步）、生成出的 Java 工程用 Maven 离线编译（本机逐个跑了一次，没有放进测试）。没有起 MySQL 跑 HTTP 业务，所以"写出来"只表示能编译，不表示业务行为已验证。

**一句话结论：**84 条需求里，58% 完整写出，12% 带折扣写出，30% 写不出。普通的增删改查、分页搜索、登录与归属、状态流转、简单的角色判断，这套语言写得下，而且很短：每个题目 150 到 320 行 SIR，生成 2400 到 3500 行 Java、10 到 21 个接口。写不下的集中在四类：**原子计数与库存、对多行的存在与统计、多个字段联合唯一、对列表的循环**。另外发现两类缺陷：语言检查放过了、但生成的 Java 编不过的写法。

## 3. 各题的需求与结果

记号：✓ 写出；✗ 写不出，后面是缺口编号（第 4 节）；△ 写出但有折扣，说明在括号里。

**校园二手交易（market）**
✓ 注册登录；✓ 卖家发布、改、删自己的商品（Crud）；△ 卖家改商品时可以把状态改成已售出（Crud 不能排除字段，G9）；✓ 按关键字浏览在售商品；✓ 商品详情；✓ 购买（并发下只有一人买到，用守卫更新）；✓ 不能买自己的；✓ 我的订单；✓ 卖家看卖出的订单（下单时把卖家抄到订单上）；△ 取消订单并重新上架（订单读不出它的商品，要客户端把商品编号再传一次，D1）；△ 订单里显示商品信息（视图只能显示商品编号，D2）；✗ 按价格区间、成色等可选条件筛选（G7）。

**图书借阅（library）**
✓ 注册、读者与馆员两种角色；✓ 馆员添加副本、按条码借书（副本状态守卫，并发只有一人借到）；✓ 书名或作者检索；✓ 续借一次；✓ 我的在借；✓ 馆员看逾期；△ 还书（要重扫条码，D1）；△ 馆员维护图书目录（Crud 不能按角色限制，任何人都能改，G9）；✗ 每人最多借 5 本（G2）；✗ 书目显示可借数量（G8、G11）；✗ 逾期罚款 = 天数 × 费率（G6）；✗ 预约已借出的书（要查"有没有人在排队"，G2）。

**在线选课（course）**
✓ 管理员建课；✓ 搜索课程；✓ 我的选课；✓ 教师看自己课程的名单；△ 选课（容量检查能写，但并发下会超卖，G1）；△ 退课（座位数同样不安全，G1）；✗ 不能重复选同一门（G2、G3）；✗ 时间冲突检测（G2）；✗ 显示剩余名额（G11）；✗ 先修课检查（G2）。

**校园博客（blog）**
✓ 注册；✓ 作者管理自己的文章（Crud）；✓ 草稿发布（守卫更新）；✓ 公开列表与搜索；✓ 按分类看文章；✓ 评论分页；✓ 删除自己的评论；✓ 分类管理；✗ 按多个标签看文章（G4，改成了单个分类）；✗ 文章页同时带出评论（D4）；✗ 每人只能点一次赞（G3）；✗ 点赞数并发不丢（G1）。

**任务看板（tasks）**
✓ 项目增删改查（Crud）；✓ 项目所有者建任务；✓ 指派；✓ 被指派人改状态；✓ 项目任务按状态分页；✓ 我的任务；△ 逾期任务（到期时间不能为空，G7）；✗ 项目成员也能看和改（G2）；✗ 未指派的任务（G7）；✗ 多条件可选筛选（G7）。

**网上商城（shop）**
✓ 管理员加商品；✓ 搜索在售商品；✓ 支付（守卫更新）；✓ 发货；✓ 我的订单；✓ 订单明细；△ 下单（只能一次买一件，G5、G6；库存扣减并发会超卖，G1）；△ 取消订单（不退库存，G5）；✗ 一个订单多个商品（G5）；✗ 金额 = 单价 × 数量（G6）；✗ 购物车（G5）；✗ 优惠券（G2、G6）。

**会议室预约（booking）**
✓ 管理员加房间；✓ 房间列表；✓ 预约时间合法（结束晚于开始、不在过去、不超过 8 小时）；✓ 开始前才能取消；✓ 我的预约；✓ 房间日程（按时间窗口）；✗ 不能与已有预约重叠（G2、G3）；✗ 每周重复预约（G5）。

**个人记账（ledger）**
✓ 分类管理（Crud）；✓ 记账增删改查（Crud）；✓ 按时间区间看账目；✓ 按分类和区间看账目；✓ 预算的增删改查；✗ 月度每类合计（G8）；✗ 预算超支提示（G8）；✗ 图表数据、导出（G8、G14）。

## 4. 缺口（写不出）

严重度按"在这八题里挡住了多少需求"估。

| 编号 | 缺什么 | 影响的题目 | 证据 | 严重度 |
| --- | --- | --- | --- | --- |
| G1 | **原子计数**：库存、座位、点赞数要"读到够再减一"并且并发下不超卖。守卫更新的绑定值不能读自己的字段；带 `versioned` 的实体只能由它的局部更新输入修改；普通的"读、改、写"能写但会丢更新 | course、shop、blog | 试写：`SIR-VALID-004`（版本实体在非局部更新里修改）、`SIR-VALID-007`（守卫读自身字段）；普通更新能编译但不安全 | 高 |
| G2 | **对多行的存在与计数**：工作流里不能问"有没有这样的行""有几行"。`any(...)` 只能出现在 `find` 的谓词里，`find` 的结果没有任何成员可用 | library、course、tasks、booking、shop | 试写：`rows.empty`、`rows.count` 报"不能访问此类型的成员"；`validate any(...)` 是 `SIR-FLOW-005` | 高 |
| G3 | **联合唯一**：几个字段合起来不重复（一人一课、一人一赞、一间房一个时段）。语法里没有，唯一只能给单个字段 | course、blog、booking | 试写 `unique (a, b)` 是语法错误；迁移工具遇到复合唯一索引也会拒绝 | 高 |
| G4 | **按用户选的值穿过关联过滤**："带标签 X 的文章"需要 `any(PostTag, post == item and tag == 请求里的值)`，语义检查放过，生成时被拒绝（"目标不能表达存在条件"） | blog | 试写：`SIR-LOWER-FEATURE-001` | 中 |
| G5 | **对列表循环**：请求里带一个列表、工作流逐项处理；对一批行统一改或删（订单行、级联删除、重复预约）。输入可以声明 `List<Id>`，但没有办法遍历它；也没有 `delete ... where` | shop、booking | 试写：`load` 用列表当主键报类型不兼容；`delete Comment where ...` 是语法错误 | 高（对商城） |
| G6 | **乘法**：只有 `+` 和 `-`。金额 = 单价 × 数量、罚款 = 天数 × 费率都写不出 | shop、library | 试写 `*` 是词法错误 | 中 |
| G7 | **可选值**：可选字段不能和值比较（`assignee == actor`、`dueAt < now()` 都是类型不一致）；没有空值判断（`none` 未定义；`.present` 只能用于局部更新的输入）；可选的请求参数当筛选条件时，生成的是 `eq(列, null)`（见 D3）。所以"可选筛选条件""未指派的任务"都写不出，任务看板只好把指派人、到期时间都做成必填 | tasks、market | 试写：`SIR-TYPE-001`、`SIR-FLOW-001` | 高 |
| G8 | **聚合**：求和、计数、平均、分组。记账的核心就是这个 | ledger、library | 没有对应语法 | 高（对记账） |
| G9 | **Crud 不够用**：不能按角色限制（图书目录任何人都能改）；不能排除字段（卖家能把商品直接改成已售出）；路径只能是一段（`path: my/posts` 是词法错误）；没有"公开读、本人写"的组合。这些都得退回手写五个能力 | library、market、blog | 内置功能的参数只有 `entity`、`owner`、`path` | 中 |
| G10 | **金额**：`Money`（十进制）交付规划不支持，只能用整数的分 | shop、ledger | 交付规划报"Decimal 需要明确的精度" | 中 |
| G11 | **视图里的计算字段**：剩余名额 = 容量 − 已选 这类展示值，视图字段必须是实体字段 | course、library | `SIR-SYMBOL-002` | 低 |
| G12 | **重复的账号样板**：每个题目都要写 `Register`、`UserView`、`use DualTokenLogin` 共约 35 行，八题一模一样 | 全部 | — | 低 |
| G13 | **写作上的小磕绊**：`fails` 必须按错误名排序；`order`、`item`、`from` 是关键字不能当名字；这些让模型更容易写错，却不影响能做什么 | 全部 | `SIR-VALID-001`、`SIR-PARSE-001` | 低 |
| G14 | **本来就不在范围内**：文件上传、发邮件短信、定时任务（订单超时自动取消）、调用外部服务、实时推送、前端 | — | — | 不算缺口，写进边界 |

## 5. 缺陷（语言检查放过，生成的 Java 编不过或结果不对）

写第一版时，八个题目里有六个生成出来的 Java 编译失败，原因是下面这几处。它们比"写不出"更糟，因为 SIR 这一关是绿的。这次为了拿到能编译的样例，源码里绕开了它们，每处绕法在源码的注释里有 `GAP` 标记。**这些缺陷还没有修。**

| 编号 | 现象 | 例子 | 方向 |
| --- | --- | --- | --- |
| D1（已修，见下） | `load 实体 by 行.引用.id` 通过检查，生成 `行.getXxxId().getId()`，对 `Long` 取 `getId()`，编译失败；而 `load 实体 by 行.引用` 因为类型对不上被拒绝。所以**没有任何办法顺着引用加载目标行** | 取消订单要重新加载商品、还书要加载副本、退课要加载课程、指派任务要加载项目 | 让 `load` 接受同一实体的引用值（最小改动） |
| D2 | 视图里嵌套另一个视图（如订单视图里放商品视图），在 `find` 分页读里可用，但从 `load`、`create` 之后 `return` 出来时，生成的构造器传的是编号而不是视图，编译失败 | 市场、图书、选课、博客、任务、预约六题的第一版都踩到 | 要么在这些路径上补读关联行，要么在语义检查时就拒绝 |
| D3 | 把可选的请求参数直接和字段比较（`item.kind == input.kind`），生成 `eq(列, input.getKind())`；参数为空时变成与空值比较，查不到任何行，没有错误 | 可选筛选条件 | 语义检查拒绝，或生成"为空则不加条件" |
| D4 | 视图里写子行列表（`field comments: List<CommentView>`）并从 `load` 返回，生成 `p.getPostId()`，编译失败（只有 `find` 分页读支持这种视图） | 文章详情带评论 | 同 D2 |

**D1 已修（2026-10-20）。**`load 实体 by 行.引用` 现在合法（引用里存的就是被引用行的主键），`行.引用.id` 生成的 Java 也不再多调一次 `getId()`。题目样例里为绕开它而多传的参数（取消订单的商品编号、还书的条码、退课的课程编号、指派任务的项目编号）已删掉，八个题目的生成工程改由 `TopicSamplesOfflineCompilationTest` 在 CI 里逐个离线编译。D2、D3、D4 仍未修。

## 6. 对下一步的含义

1. **先修 D1、D2。**它们让"检查通过"不再等于"生成的东西能编译"，这对第 7 节说的评测直接有害：模型写对了 SIR，仍可能因为这里编不过而被判错。D1 改动很小，D2、D4 要补"读关联行"的生成。
2. **再补 G1、G2、G3。**它们一起挡住了选课、预约、点赞、借阅上限、库存这一整类业务；其中 G3（联合唯一）最便宜，而且让数据库来兜底并发，同时解决一部分 G2。G1 需要设计：守卫允许读自身字段的算术（`SET stock = stock - 1 WHERE stock > 0`），是一条 SQL，仍然是原子的。
3. **G7（可选值的比较与空值判断）**挡住的需求条数最多，也该排在前面。
4. G5（循环）和 G8（聚合）是两个大块，都会让语言明显变复杂。建议先看 G1 到 G4、G7 补完之后，还有多少需求写不下，再决定要不要做。
5. 记账一题说明：只做增删改查和区间查询的题目，现在已经很轻松；需要"统计"的题目，会卡在 G8。毕设里统计页很常见，这条值得认真排。

## 7. 与评测的关系

这八个题目加上 `valid/` 里的双 Token 题，可以直接当小模型评测的题库：每题已有需求清单和一份参考答案，"写出"的需求就是判题点，"写不出"的需求不进判题点。评测计划（[SLM 评测计划](SLM_GENERATED_PROJECT_EVALUATION_PLAN.md)）要求的四道门里，"构建"这一道已经被 D1、D2 证明会出问题，所以应当先修它们再评测。
