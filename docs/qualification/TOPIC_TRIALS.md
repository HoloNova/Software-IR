# 选题试写：用 SIR 写八个典型后端，看语言还缺什么（2026-10-20）

## 1. 做了什么，为什么

[设计 12](../design/12-feature-semantics-and-semantic-types.md) 之后语言已经能写不少东西，但"够不够"一直靠猜。这次的做法：选八个毕设、课程设计或小团队常见的后端题目，每题先列真实需求，再用 SIR 逐条写；写不出来的记下来，不绕开、不修语言。每份源码放在 `sir-toolchain-application/src/test/resources/topics/<题目>/project.sir`，由 `TopicSamplesTest` 保证它们一直是合法、能生成、能交付的软件。

原版源码经过三道检查：SIR 分析与生成、交付规划（`kcg package` 那一步）、生成出的 Java 工程用 Maven 离线编译（`TopicSamplesOfflineCompilationTest`，CI 里逐个编译，原版在本机跑过一遍）。G2/G4 修改后的八题已通过前两道，第三道留待同源码 CI。没有起 MySQL 跑这八题的 HTTP 业务，不能把“表达出来”视为业务行为已验证。

**一句话结论：**84 条需求里，76% 完整写出，6% 带折扣写出，18% 尚未写出（第一版是 58%、12%、30%；中间修掉缺陷 D1 到 D4 后是 63%、8%、29%，再加上联合唯一和唯一冲突报错后是 65%、10%、25%，补上原子计数后是 69%、7%、24%，补上 G7 可选值后是 74%、6%、20%，补上 G2/G4 后是现在的数字）。普通的增删改查、分页搜索、登录与归属、状态流转、简单的角色判断，这套语言写得下，而且很短：每个题目 150 到 400 行 SIR，生成约 2300 到 4100 行 Java、10 到 22 个接口。写不下的集中在三类：**多行业务的并发与关联组合、对列表的循环及分组统计**。另外发现两类缺陷：语言检查放过了、但生成的 Java 编不过的写法。

## 5. 缺陷（语言检查放过，生成的 Java 编不过或结果不对）

写第一版时，八个题目里有六个生成出来的 Java 编译失败，原因是下面这几处。它们比"写不出"更糟，因为 SIR 这一关是绿的。第一版为了拿到能编译的样例，绕开了它们。**现在都已修好（见表后）。**

| 编号 | 现象 | 例子 | 方向 |
| --- | --- | --- | --- |
| D1 | `load 实体 by 行.引用.id` 通过检查，生成 `行.getXxxId().getId()`，对 `Long` 取 `getId()`，编译失败；而 `load 实体 by 行.引用` 因为类型对不上被拒绝。所以**没有任何办法顺着引用加载目标行** | 取消订单要重新加载商品、还书要加载副本、退课要加载课程、指派任务要加载项目 | 让 `load` 接受同一实体的引用值（最小改动） |
| D2 | 视图里嵌套另一个视图（如订单视图里放商品视图），在 `find` 分页读里可用，但从 `load`、`create` 之后 `return` 出来时，生成的构造器传的是编号而不是视图，编译失败 | 市场、图书、选课、博客、任务、预约六题的第一版都踩到 | 要么在这些路径上补读关联行，要么在语义检查时就拒绝 |
| D3 | 把可选的请求参数直接和字段比较（`item.kind == input.kind`），生成 `eq(列, input.getKind())`；参数为空时变成与空值比较，查不到任何行，没有错误 | 可选筛选条件 | 语义检查拒绝，或生成"为空则不加条件" |
| D4 | 视图里写子行列表（`field comments: List<CommentView>`）并从 `load` 返回，生成 `p.getPostId()`，编译失败（只有 `find` 分页读支持这种视图） | 文章详情带评论 | 同 D2 |

**四处缺陷都已修（2026-10-20）：**
- D1：`load 实体 by 行.引用` 现在合法（引用里存的就是被引用行的主键），`行.引用.id` 生成的 Java 也不再多调一次 `getId()`。
- D2、D4：`load` 或 `create` 之后 `return` 的那一行，现在可以带嵌套的视图，一对一和一对多都行。做法和分页 `find` 一样，每个嵌套多一条批量查询（返回步骤在中间表示里声明条数，校验时核对）。一对多读出全部子行，不分页。
- D3：最初在 `find` 谓词里拒绝可选值比较以免猜含义；G7 已以明确的空值规则替代拒绝：普通比较遇空为 false，需要跳过条件就显式写空值判断，不静默跳过。

题目样例里为绕开 D1、D2 而多传的参数、改成编号的视图字段都已还原成自然写法（订单里带商品、课程里带教师、文章页带评论列表），八个题目生成的工程由 `TopicSamplesOfflineCompilationTest` 在 CI 里逐个离线编译；旧版在本机跑过一遍并通过；本轮更新版只完成内存生成与规划，生成工程编译留给同源码 CI。

## 7. 与评测的关系

这八个题目加上 `valid/` 里的双 Token 题，可以直接当小模型评测的题库：每题已有需求清单和一份参考答案，"写出"的需求就是判题点，"写不出"的需求不进判题点。评测计划（[SLM 评测计划](SLM_GENERATED_PROJECT_EVALUATION_PLAN.md)）要求的四道门里，"构建"这一道已经被 D1、D2 证明会出问题，它们现已修好，并由离线编译测试守住。
