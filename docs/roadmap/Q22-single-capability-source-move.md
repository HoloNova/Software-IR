## 1. 用户场景与交付目标

课程工程已经保存四份SIR源，报名查询能力SearchCourseEnrollments带 `@id("search-course-enrollments")`，当前在project.sir。用户复制保存快照，把**这一个完整能力声明**剪切到modules/search.sir，保留声明名称、@id、合同和工作流，只补必要的sources/imports；提交候选快照。

本单交付：**明确选择移动的能力及目的文件 → 只读核验/计划 → 保存候选全部源、图及清单 → 发布新CURRENT → 新实例从新位置重开 → 用Q21修改已移动能力的查询条件。**

移动时生成工程的完整受管文件集合和每个文件字节必须完全不变，不重写Java、不重建/启动应用、不碰数据库。源快照和Graph的真实位置发生变化，故基线ID可以改变；不能把“Java没有变化”当作“不必保存新源”。后续修改查询时才由已有Q21执行文件UPDATE。

这不是增加课程特有语法或再实现一套业务：移动继续组合已有Parser/Resolve、源快照、生成、基线与安全发布。修复的是“源组织变化但输出不变时如何保留可继续编辑的基线”这一类缺口；共用机械能力，首轮用单能力约束验收范围。

目标不是任意文件整理工具：本单不自动剪切原源目录，也不要求工具猜旧→新声明。输入是用户准备的不可变完整候选快照；保存发生在工具管理的基线目录。scope仅一个已带@id的capability，不含实体/字段/Input/View移动、改名、多声明组合、同时修改业务或通用格式化发布。

## 3. 推荐范围与判定规则

### 3.1 显式对象，不猜移动

请求明确stateRoot/outputRoot、expectedBaselineId、选中的基线capability SymbolId及目的SourceId，并携完整候选SourceSnapshot。目标必须来自本次基线目录，旧名称/旧位置不是匹配算法；基线与候选中主体的显式@id、SymbolId和名称必须相同。

只允许主体从一源文件变到另一个源文件：根→片段、片段→根、片段→片段。入口project.sir不能改名/换路径；目的片段可已存在，或在候选中显式新增。原片段仅在移动后无任何声明时才允许从候选sources清单撤下；含其他声明必须保留。不扫描目录、不接受未列源、不删除用户原源文件。

所有非主体声明的种类/ID/名称/正文及所属源文件保持；每个文件中非主体声明的相对顺序保持。剪切导致的行号、AST路径/序号变化不误认为新业务；不得据此忽略结构或绑定。metadata、software与target保持。sources/imports仅为新增/移除空片段、让原引用在新位置合法而调整，逐项验证成员闭包和实际绑定，不允许顺带改导入目标或形成其他合法但不同的业务。

未带@id的capability本单明确拒绝，不自动补ID或暗中迁移旧身份。相同名字但换@id、声明删除后同名新建、重复ID、根/目的文件不匹配都不是移动。

### 3.2 业务相同、绑定正确、位置真实，三者各自举证

主体声明的Parser跨度内原UTF-8字节必须相同（不为缩进/换行作归一化）；允许声明外为剪切/粘贴产生的空白和必要sources/imports调整。不支持同时改工作流/合同/注释正文或任意格式化后发布。非主体声明正文同样按解析跨度原字节核对；字符串/Unicode/BOM/CRLF不静默改写。跨度换算必须按当前source code-point契约，不能混用Java char索引和原字节偏移。

完整两侧源从原字节分别解析/Resolve/Type/Validate/Normalize，不复用旧AST或旧位置。比较完整软件语义、声明集合和实际解析出的引用，不仅比较Service字节或过滤变量后的13个目标列表。

引用对应关系按**拥有者声明+声明内结构位置+ReferenceRole**建立本次移动的核验证据：外部声明/字段目标SymbolId不变；局部变量按两侧同一语法结构中的声明槽对应，验证每个引用仍指向相同局部声明槽，拒绝漏项/重复/越域。不按变量名或排序后的目标集合猜配对；具有相同变量名的不同作用域不能混淆。这个对应关系只用于验证当前纯移动，不作为写进SIR的持久nodeKey，也不宣称局部SymbolId或引用点AstNodeId跨移动稳定。

含sourceNodeId的旧工作流合同比较不能直接作为移动合同。推荐新增纯移动专用比较，保留原UPDATE语义和守卫；通用、无位置的比较部分能共享才提取，禁止给全部变更操作放宽身份检查。新比较若需要补nodeKey/修改语言或现有Normalize语义，先停轮报告，不暗中扩单。

完整B0/B1受管manifest每个字段（路径/字节数/SHA/artifact/owner）相同，Application再核对**每个实际候选生成文件的原字节**。相同源码正文和相同输出都不是独立的来源认证；Application的两侧重新编译才是执行依据。Graph中的source manifest、span/sourceNodeId必须指向候选真实位置，图摘要不要求相等。

### 3.3 独立只读计划与执行入口

推荐新增专用typed SourceMove计划/context/执行合同（命名、字段、诊断及版本由P2冻结）：绑定两侧完整源revision/图/manifest、基线凭据、显式subject与from/to、声明正文/结构及引用对应证据、state/output根和本次完整计划摘要。计划明确**生成文件变化为空**，不制造FileChange或空ProjectChangePlan。

Pure规划/复核只比较不可变数据；Application读取完整保存源并从候选原字节重编译。同一已有StateRootLock内重新取得基线、重建context/计划、逐字段比对调用方预期、核验整个输出盘面和根身份后才写状态；不能公开verify后释放锁再执行。自洽hash、另一根/另一候选的计划和外部完整孤包都不授予执行资格。

精确同一完整源快照无实际移动可返回明确NoChanges、零状态写入；仅注释/导入排列变化而没有主体移动拒绝为超范围，不自动发布“所有源码等价修改”。已有Q20/Q21 NoChanges继续不发布。已发布后旧B0计划应陈旧拒绝，不自动重放；新当前快照的精确重复与recover幂等分别验证。

### 3.4 只发布源基线，不写生成工程

沿用Q19四成员Bundle、descriptor/源容器/Graph格式与基线ID域。先保存完整B1原源字节/真实图/相同受管清单，建立可复核的纯移动绑定与发布材料；再次核验完整编译证据/输出盘面/B0 CURRENT后发布B1。新实例inspect与Q20context必须读到新位置，并能从新位置规划Q21工作流修改。

源发布只有CURRENT这一个提交方向，不能引入“源CURRENT”第二head、覆盖旧B0目录或偷换初次register合同。保留必要的独立完成凭据，受控接入既有历史读取；SourceMove→Q21 UPDATE及Q21 UPDATE→SourceMove混合历史必须实际通过，不能第一次移动后把guard堵住。

Q21 UPDATE binding/journal/receipt原字节与“至少一个真实UPDATE”不变量不变。推荐专用源发布凭据/状态图，优先提取共享安全发布/严格framing/锚与有界历史读取；具体哪些数据格式可共享、是否需新的显式版本/族，在P3–P4实证冻结。不得暂时允许updates为空来复用旧恢复引擎；不写另一个脱离历史门禁的CURRENT发布器。未知版本、非对应日志族仍拒绝保留。

历史预算仍统一计数，不给新族另开32份无限叠加：沿Q21的8 Bundle/32关系/32终态凭据/64 MiB累计限制，Q19源/图/manifest/路径限额不放宽；新单次材料/记录/事件限额P3冻结，写前检查、逐项枚举/编码/读取。达到上限明确拒绝，不自动GC。

### 3.5 中断与显式恢复

首次写状态前的拒绝必须输出根和状态根零修改；准备后失败用明确处置/handle区分未发布、已发布待清理、证据不明，不能把已有部分状态写入报成零副作用。

- CURRENT=B0：只能清理经验证属于本次源发布的未提交材料，保持B0源基线；**不写/回滚Java**。
- CURRENT=B1：核验完整候选源/图/清单与仍相同的工程，完成本次发布后收尾，绝不回退B0。
- CURRENT缺失/第三值、B0/B1或归属/日志/物理锚损坏、未知文件、输出被外部改动：拒绝并保留，不修复/覆盖用户工程。

继续使用同字节外部替换反例和保留硬链接锚，不只比fileKey+SHA；半写新日志不得毁掉最后有效恢复证明。有效准备到发布/清理的每个检查点、新实例恢复及恢复中再次中断分列；无完整证据的准备像保留拒绝，不冒称全部可恢复。读入口只报告阻塞，不清空目录/隐式恢复。重复恢复幂等；历史移动基线不可作为未提交候选删除。
