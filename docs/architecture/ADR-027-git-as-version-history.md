# ADR-027：以 Git 和磁盘上的 SIR 作为版本历史，取代自存历史

- Status: **Accepted for G1**（2026-10-14，负责人确认第 6 节的三项并授权开始 G1；G1 已实现，见[G1 报告](../roadmap/G1-workspace-version-report.md)；G2 至 G4 仍按计划分阶段确认）
- 起因：负责人 2026-10-14 的决定——使用 Git；工具链升级后按最新版本重新生成；明确**不支持用户手改生成的代码**；旧的无用测试和被本决定弃用的代码逻辑允许直接删除。
- 影响的已验收 ADR：[ADR-022](ADR-022-multi-source-baseline-storage-and-reopen.md)、[ADR-024](ADR-024-project-workflow-update-publication-and-recovery.md) 的存储、历史、事务与恢复部分；[ADR-026](ADR-026-layered-semantic-command-architecture.md) 的 R3/R4 版本事务部分。**不改**：解析、语义、降级、生成、指令编辑、R5 独立验证。
- 计划：[G 系列迁移计划](../roadmap/G-git-version-history-plan.md)。

## 1. 要解决的问题

系统为了"改一半断电也不出错"和"能回到旧版本"，自己保存了版本、历史、回执和事务日志。结果是：

- 存储相关代码约 1.5 万行（`internal/state` 约 1.17 万行，`bundle`、`projectbaseline`、`projectupdate`、`version` 合计约 4600 行）。
- 版本数量要设上限（8 个版本、32 条关系），到了上限要做"状态目录换代"。
- 每次打开都要把全部历史读一遍核对。

这些都是"自己做版本管理"带来的成本。版本管理本来就是 Git 的工作。

## 2. 决定

1. **当前版本的权威是磁盘上的 SIR 源码；历史的权威是 Git。** 系统不再保存版本历史、发布关系、回执和事务日志。
2. **生成的工程不允许手改。** 受管文件与"当前 SIR 的编译结果"不一致，一律视为需要重新生成，由用户处理。不做"区分手改和工具链变化"。
3. **工具链升级后，按最新工具链重新生成。** 升级造成的差异和手改一样，报告为"需要重新生成"。
4. **断电或中断后需要重跑时，系统只给出明确提示，由用户自行重跑。** 系统不自动恢复，也不保证中途状态可回退，回退交给 `git`。
5. **Git 通过端口接入**，放在应用层公开接口里，适配器调用 `git` 命令（与构建、启动适配器同一种做法）。允许自动初始化仓库，并在应用前后保存快照。

## 3. 已核对的事实（不是假设）

| 事实 | 位置 |

## 4. 已知后果与限制

1. **整体核对会包含工具链升级造成的差异**：升级后"编译当前 SIR"得到的结果与磁盘上旧工具链生成的不同，所有受影响文件都会被报告。处理方式是整体重新生成。
2. **旧工具链多生成、新工具链不再生成的文件会残留**：系统不知道旧工具链的文件清单。靠 Git 的 `status` 和 `diff` 发现并处理。
3. **重跑要求"应用"对半途状态宽容**：磁盘上的文件如果已经等于候选版本的字节，应视为"已应用"，不能报告成被手改。这是对现有冲突规则的一处新增。
4. **不再提供崩溃后的自动回退和一致性证明。** R4 的故障矩阵证据只对旧事务成立，新路径需要它自己的证据（见计划）。
5. **失去的能力**：回到旧版本由 `git checkout` 负责，不再由系统提供；版本数量上限和状态目录换代随旧代码一并删除。
6. **Git 只保护已提交的内容**：未提交的改动仍可能被覆盖。应用前自动快照用来缩小这个风险，不能消除。

## 5. 不做

- 不改 SIR 语言、解析、语义、降级、生成。
- 不改指令编辑（`SourceEditor`）。
- 不改 R5 的验证合同；`VerifiedVersionApplication` 只改成依赖接口。
- 不支持用户手改生成的代码，也不做冲突合并。
- 不自动推送到远端。

## 6. 负责人的决定（2026-10-14）

1. SIR 源码和生成的工程放在**同一个 Git 仓库**。
2. 自动快照的范围是 SIR 源码和受管生成文件，应用前后各一次，不推送；用户自己的其他文件和已暂存内容不被带入快照。
3. **没有 `git` 可用时拒绝应用**，不记为未执行后继续。
4. 旧的无用测试和被本决定弃用的代码逻辑允许直接删除，仍按计划 G4 分批进行。
