# ADR-026：以统一软件语义支撑指令式增删改和独立工程验证

## 状态

**Accepted for architecture direction，2026-10-13。**

负责人确认首次生成／指令修改工作流和分层方向，授权详细方案、工程文档更新、提交与推送，并允许优化方案。该接受记录只冻结方向与职责，**不授权生产代码实施，不宣称新接口或新事务已实现**。详细合同与迁移门见[设计08](../design/08-layered-command-architecture.md)及[迁移路线](../roadmap/LAYERED_ARCHITECTURE_MIGRATION.md)。

源码起点 `dac046309686b8bbb910624bbed04717e7481b2f`。当前活动单 Q23 的功能/验收推进暂停；Q22继续暂停；旧组合原型草案不直接成为下一张实施单。

## 背景

当前工具链已有 Parser→Semantic→Lowering→Generator 分层，但 Change 使用六类专用操作、手写 SemanticProjection、单项 ChangeSet 和不可混合的 ChangePlan。普通跨声明组合常需预置依赖或拆轮；新增语言结构还需在 Change 补投影。

现有 Normalized model 已包含正式 binding 和类型结果，不能直接修改后沿用旧分析。多源 Graph 只有生成归属边，不是完整依赖图。当前事务有严格的单项/UPDATE-only/日志格式合同，不能通过放宽构造器把它们冒称为通用执行器。

## 考虑的方案

| 方案 | 结论 |
| --- | --- |
| 继续添加专用操作，或仅将它们改名为增删改 | 不采用；语言知识、准入和文件影响仍重复耦合 |
| 在 Change 注册逐变化 Java 策略 | 不作为最终架构；可研究组合，但仍需为新语义补 Change 侧规则，不满足本次方向 |
| 无类型 JSON 树、全 record 反射或用户规则 DSL | 不采用；不能明确区分软件事实、位置、派生 binding 和强类型不变量 |
| 语义拥有类型化结构合同，固定机械增删改，复用正式编译与生成 | **采用**；结构编辑通用化，领域合法性与目标实现仍有唯一归属 |

## 决定

1. SIR 表达软件，Java 为派生产物。首次生成与后续修改共用同一套语义检查、Lowering 和 Generator。
2. Semantic 拥有 SoftwareSchema、可编辑草稿与已验证快照。结构定义显式分类属性、子内容、引用、有序性、来源和派生字段；不在 Change 再手写一份语言投影。
3. Change 内核固定 **Add/Delete/Update** 三种操作，机械编辑与语义比较。允许同批组合；不以业务种类/具体结构添加操作或策略。
4. 草稿不是已验证模型；指令不写 binding/type/缓存。结构化源写出后，由候选原字节完整运行一次正式 Parse/Resolve/Type/Validate/Normalize。名称仍只在这次 Resolve 建立绑定。
5. 稳定身份、基线/修订绑定的选择器和前置条件用于编辑；不按名称相似性猜改名，不承诺未实现的永久 nodeKey。源位置与业务事实分开。
6. 源表示/writer 归解析层结构 API；语义到源的转换归语义协作；Parser 不反向依赖 Semantic，不把文本替换和业务判断放 Change。
7. Lowering 拥有目标支持与实现决策，Generator 纯渲染。实际依赖下载、构建、启动、业务判分归独立执行端口，不嵌入解析或静态校验。
8. Application 唯一拥有工程状态，并比较完整受管文件集合。SemanticDelta 与 FileDelta 分开；新计划需承载混合文件差异、source-only 版本发布及完整保存源。Graph 继续提供来源，不当依赖求解器。
9. 新的工程应用协议按阶段另审，保持一个 CURRENT 及 ADR-020 的恢复方向；不重解释旧 Bundle/Plan/Journal，不绕过锁内核验或文件归属证明。
10. 先统一模型合同和编排，不同时全量重写编译器、引入新增量编译/缓存、数据库迁移、第二 Target 或 Web 平台。九模块优先保留，按真实依赖再评审拆分。

## 兼容与裁决范围

本 ADR 是新入口的目标架构，**不取代旧入口的执行合同**：ADR-001 的 Resolve-once、ADR-003 的 Application ownership、ADR-020 的 CURRENT 方向继续适用；ADR-021～024 的现有格式、版本拒绝、NoChanges、UPDATE-only、来源/历史/预算不变；ADR-025 的 Q23 静态协议也不因此变成运行服务。

新模型、源往返、通用只读计划和新的工程应用通过各自门后，才安排旧入口适配/退役。旧资格证据保留，不用新方向降低旧测试断言。数据库变化由 G3 独立处理，文件事务不抵扣数据库门。

## 后果与验证

新增普通业务应主要组合已有语义；新增语言能力的变化应集中在 Parser/Semantic/Target，而不是额外补 Change。初期成本是完整语义字段分类、强类型适配、SIR 编辑/往返，以及新旧发布协议的明确兼容。

需证明：全字段变化可见、位置不混成业务、组合修改无需业务特判、新语义结构无需改 Change、生成与从零逐字节一致、保存源可重开、混合及 source-only 发布可恢复、真实业务判分独立。接口只是设计时所有新门记 NOT_RUN。

通用协议变化或内核缺陷仍可能维护 Change；本决定不许诺永不改动。实现授权只由负责人后续明确批准的工作单给出；本轮文档提交/推送不是开工许可。
