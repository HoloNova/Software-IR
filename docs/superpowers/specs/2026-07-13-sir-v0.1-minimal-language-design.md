# SIR v0.1 最小语言设计

状态：第一轮已确认  
日期：2026-07-13  
上位规范：`Software IR v0.1 架构基线`  
长期兼容边界：`Software IR 扩展与增量修改规范`

## 1. 第一轮目标

本轮只冻结最小 SIR 的元素、唯一语义和错误标准，不编写完整 Parser 或 Generator。

最小语言必须能描述：

- 一个软件的身份；
- 固定的 Spring Boot 目标配置；
- Entity、Enum、Input 和 Error；
- Capability 的输入、输出和执行者；
- 有限、无循环的业务流程；
- 持久化、事务、权限和 REST 暴露意图。

本轮不支持：

- 任意 Java 表达式；
- loop、parallel、retry 和 compensation；
- 外部服务调用；
- 自定义函数；
- 继承和泛型声明；
- Redis 缓存语义；
- 用户自定义 Maven 坐标；
- Controller、Service、Mapper、注解和 SQL。

Redis 查询缓存保留为 Core 主链完成后的第一个 Extension，不混入本轮最小 Core。

## 2. 唯一表达原则

### 2.1 每个事实只有一个声明位置

- 项目版本和命名空间只在 `metadata`；
- 技术栈只在 `target`；
- 类型只在对应类型声明；
- 持久化意图只在 Entity 头部；
- API 暴露只在 Capability 内；
- 权限和事务只在 Capability 的 `requires` 中。

### 2.2 每个动作只有一个关键字

- 保存统一为 `persist`，不提供 `save`、`store` 或 `insert`；
- 修改统一为 `update`，不提供 `set` 或 `patch`；
- 查询单个对象统一为 `load`；
- 查询多个对象统一为 `find`；
- 失败校验统一为 `validate ... else ...`。

### 2.3 可空性只由类型表达

必填字段写：

```text
field title: String;
```

可缺失字段写：

```text
field description: Optional<String>;
```

不提供 `required`、`nullable` 等第二套表达。

### 2.4 Core 不出现目标框架元素

SIR 写：

```text
persist goods;
requires atomic;
expose command;
```

SIR 不写：

```text
goodsMapper.insert(goods);
@Transactional;
@PostMapping;
```

## 3. 文档顶层结构

一份 v0.1 文档必须按以下顺序出现：

```text
sir 0.1

software CampusMarket {
  metadata { ... }
  target { ... }
  declarations { ... }
}
```

三个区块各出现一次，不能省略、重复或改变顺序。固定顺序可以减少 SLM 输出空间，也简化 Parser 和 Canonical Form。

### 3.1 `sir`

表示文本使用的语言版本，不是生成项目版本。

v0.1 只接受：

```text
sir 0.1
```

### 3.2 `software`

声明唯一软件单元。名称必须是 PascalCase 标识符，在文档内不可重复声明第二个 `software`。

### 3.3 `metadata`

```text
metadata {
  displayName "校园二手交易系统";
  namespace "com.example.campusmarket";
}
```

- `displayName`：面向人的名称，不参与 Java 符号解析；
- `namespace`：目标项目基础命名空间，必须符合 Java package 片段格式；
- 两个字段都必填且只能出现一次。

### 3.4 `target`

```text
target {
  language java 21;
  framework spring_boot;
  persistence mybatis_plus;
  database mysql;
  build maven;
  interface rest;
}
```

第一轮只接受以上固定值。Target Profile 根据这六个选择填充经过测试的实际依赖版本；SIR 不允许直接写 Maven groupId、artifactId、仓库 URL 或版本号。

## 4. 声明元素

`declarations` 中只允许五种顶层声明：

1. `enum`；
2. `entity`；
3. `input`；
4. `error`；
5. `capability`。

Extension 在未来版本通过独立、版本化的扩展包络加入；本轮拒绝未知 Extension。

顶层名称共享同一个命名空间，不允许 Entity、Input、Error 或 Capability 同名。这一限制比多命名空间严格，但能减少 v0.1 的歧义。

### 4.1 Enum

```text
enum GoodsStatus {
  AVAILABLE,
  SOLD
}
```

语义：有限且封闭的命名值集合。

规则：

- 至少一个成员；
- 成员使用 UPPER_SNAKE_CASE；
- 成员名不可重复；
- 不支持自定义数字或字符串值。

### 4.2 Entity

```text
entity Goods persistent {
  identity id: Int64 generated auto;
  field title: String where notBlank;
  field description: Optional<String>;
  field price: Decimal where min(0.01);
  field seller: Ref<User>;
  field status: GoodsStatus;
}
```

语义：具有稳定业务身份的对象。`entity` 不等同于数据库表或 MyBatis-Plus Java 类。

规则：

- 每个 Entity 恰好一个 `identity`；
- `persistent` 表示需要持久保存；
- v0.1 的 Entity 全部要求 `persistent`，但保留显式关键字以固定语义；
- identity 类型只允许 `Int64` 或 `Uuid`；
- `generated auto` 只适用于 `Int64`；
- `generated uuid` 只适用于 `Uuid`；
- Field 名在 Entity 内唯一；
- Entity 之间只能通过 `Ref<Entity>` 引用，不能把 Entity 名直接作为字段类型。

### 4.3 Input

```text
input PublishGoodsInput {
  field title: String where notBlank;
  field price: Decimal where min(0.01);
}
```

语义：Capability 边界接收的数据，不具有身份、不能持久化。

Input 不能继承 Entity，也不能直接替代 Entity。这样可以避免把数据库对象直接作为外部请求模型。

### 4.4 Error

```text
error GoodsNotFound;
error GoodsUnavailable;
```

语义：业务流程中可预期、可声明的失败结果。

v0.1 Error 不携带自定义字段。HTTP 状态码由 Target Lowering 根据 Error 分类表决定，不进入 Core SIR。

### 4.5 Capability

```text
capability PublishGoods {
  actor Ref<User>;
  input PublishGoodsInput;
  output Ref<Goods>;
  fails InvalidGoodsPrice;

  requires authenticated;
  requires atomic;
  expose command;

  workflow {
    ...
  }
}
```

语义：系统对外提供的一个完整业务能力。

字段和规则：

- `actor` 可选；存在时表示当前执行者，不是普通请求字段；
- `input` 可选且最多一个；复杂输入必须先声明为 Input；
- `output` 必填；无返回值使用 `Unit`，Workflow 以唯一形式 `return unit;` 结束；
- 每一种预期失败都必须通过 `fails` 声明；
- `requires` 只允许 `authenticated`、`atomic`、`readonly`；
- `atomic` 与 `readonly` 互斥；
- 多个 `fails` 必须去重并按 Error 名称升序排列；多个 `requires` 必须去重并按 `authenticated`、`atomic`、`readonly` 的固定顺序出现；
- `expose` 必须是 `command` 或 `query`；
- `query` 必须声明 `readonly`，且 Workflow 不能包含 create、update 或 persist；
- `command` 不强制 atomic，但包含多个写步骤时 Validator 应要求 atomic。

## 5. 最小类型系统

### 5.1 基础类型

```text
Boolean
Int32
Int64
Decimal
String
Uuid
Date
DateTime
Unit
```

### 5.2 构造类型

```text
Optional<T>
List<T>
Ref<Entity>
```

规则：

- `Optional<Optional<T>>` 非法；
- `Ref<T>` 的 T 必须是 Entity；
- Primitive 是预声明且不可遮蔽的全局类型符号，用户声明和 Workflow 局部变量不得复用这些名称；
- `Unit` 只允许作为 Capability 的直接 `output`，不得用于 Identity、Field、Input、actor 或任何构造类型参数，因此 `Optional<Unit>` 与 `List<Unit>` 均非法；
- `output Unit` 的正常路径必须直接返回 `AstUnitLiteral`；非 `Unit` 输出不得返回 `unit`；
- v0.1 不支持 Map、Set、Page 和用户自定义泛型；
- Entity 只以 `Ref<Entity>` 出现在字段、actor 和 Capability 输出中；
- `T` 可以赋给 `Optional<T>`，反向不可；
- 不进行隐式数字类型转换。

### 5.3 Field 约束

v0.1 只支持：

```text
notBlank
email
min(number)
max(number)
length(min, max)
```

同一 Field 上 Constraint 的顺序表示确定的校验与报错优先级，因此它是有序语义，不按集合重排；重复 Constraint 由 Validator 拒绝。

适用规则：

- `notBlank`、`email`、`length` 只适用于 String；
- `min`、`max` 只适用于 Int32、Int64、Decimal；
- Field 约束可以附着到 `Optional<T>`，但只在值存在时检查其内部 T；
- 同一种约束在同一 Field 上最多出现一次；
- 互相冲突的 min/max 必须报错。

唯一性和索引属于持久化约束，本轮暂不加入语法；等 MySQL Lowering 设计时单独冻结，避免把字段校验与数据库索引混为一谈。

## 6. Workflow v0.1

Workflow 是有类型变量的、顺序执行、无循环业务流程。它不是任意 Java 方法体。

### 6.1 初始变量

根据 Capability 声明，Workflow 自动获得：

- `actor`：存在 actor 时可用；
- `input`：存在 input 时可用。

这两个名字为保留字，不能被步骤重新定义。

### 6.2 支持的步骤

#### Validate

```text
validate input.price >= 0.01 else InvalidGoodsPrice;
```

条件必须是 Boolean，Error 必须已在 Capability 的 `fails` 中声明。

#### Load

```text
load Goods by input.goodsId as goods else GoodsNotFound;
```

根据 identity 查询一个 persistent Entity，成功后定义 `goods: Ref<Goods>`。

#### Find

```text
find Goods where item.status == GoodsStatus.AVAILABLE as goods;
```

查询多个 persistent Entity，定义 `goods: List<Ref<Goods>>`。`item` 是仅在该查询谓词内可用的固定临时变量，类型为 `Ref<Goods>`，不能改名或在步骤外引用。v0.1 只允许等值、大小比较和布尔组合，不支持排序和分页。

#### Create

```text
create Goods as goods {
  title: input.title;
  price: input.price;
  seller: actor;
  status: GoodsStatus.AVAILABLE;
}
```

所有非 Optional Field 必须绑定一次；Optional Field 可以省略；identity 由系统生成时不能手工绑定。

#### Update

```text
update goods {
  status: GoodsStatus.SOLD;
}
```

目标必须是 `Ref<Entity>`；identity 不可修改；字段只能绑定一次。

#### Persist

```text
persist goods;
```

目标必须是 persistent Entity 的引用。Create 和 Update 只改变 Workflow 中的语义状态，只有 Persist 表示需要保存。

#### Return

```text
return goods;
```

无业务返回值时使用：

```text
return unit;
```

`unit` 是 `Unit` 的唯一字面量，不是可重命名变量。每个正常执行路径必须恰好到达一个 Return，返回值必须可赋给 Capability output。

### 6.3 表达式

只支持：

- Boolean、数字、字符串和 `unit` 字面量；
- `actor`、`input` 和局部变量；
- 字段访问；
- Enum 成员；
- `==`、`!=`、`>`、`>=`、`<`、`<=`；
- `and`、`or`、`not`；
- 唯一内建函数 `now()`。

不支持算术表达式、任意方法调用、赋值表达式或 Java 代码片段。需要新表达能力时必须先进入语言规范。

### 6.4 控制流限制

第一轮不支持 if/else。业务条件先统一使用失败式校验：

```text
validate condition else Error;
```

这样可以完成发布商品和下单的主流程，并显著降低变量合流和返回路径分析难度。if/else 是后续候选能力，不应在第一轮偷偷通过模板实现。

## 7. 完整合法示例

```text
sir 0.1

software CampusMarket {
  metadata {
    displayName "校园二手交易系统";
    namespace "com.example.campusmarket";
  }

  target {
    language java 21;
    framework spring_boot;
    persistence mybatis_plus;
    database mysql;
    build maven;
    interface rest;
  }

  declarations {
    enum GoodsStatus {
      AVAILABLE,
      SOLD
    }

    entity User persistent {
      identity id: Int64 generated auto;
      field name: String where notBlank;
      field email: String where email;
    }

    entity Goods persistent {
      identity id: Int64 generated auto;
      field title: String where notBlank;
      field price: Decimal where min(0.01);
      field seller: Ref<User>;
      field status: GoodsStatus;
    }

    input PublishGoodsInput {
      field title: String where notBlank;
      field price: Decimal where min(0.01);
    }

    capability PublishGoods {
      actor Ref<User>;
      input PublishGoodsInput;
      output Ref<Goods>;
      requires authenticated;
      requires atomic;
      expose command;

      workflow {
        create Goods as goods {
          title: input.title;
          price: input.price;
          seller: actor;
          status: GoodsStatus.AVAILABLE;
        }

        persist goods;
        return goods;
      }
    }
  }
}
```

## 8. 必须拒绝的示例

### 8.1 第二套可空表达

```text
field title: String required;
```

预期：语法错误。必填已经由非 Optional 类型表达。

### 8.2 目标框架污染 Core

```text
goodsMapper.insert(goods);
```

预期：语法错误，不允许 Java/MyBatis-Plus 调用。

### 8.3 未知类型

```text
field seller: Ref<Account>;
```

预期：符号错误，`Account` 未定义。

### 8.4 Entity 未使用 Ref

```text
field seller: User;
```

预期：类型错误，Entity 字段必须使用 `Ref<User>`。

### 8.5 未声明失败

```text
validate input.price > 0 else InvalidGoodsPrice;
```

如果 Capability 没有 `fails InvalidGoodsPrice`，预期产生语义错误。

### 8.6 Query 写入

```text
expose query;
persist goods;
```

预期：语义错误，Query/readonly Workflow 不允许写步骤。

### 8.7 返回类型错误

Capability 输出为 `Ref<Goods>`，但 Workflow：

```text
return input.title;
```

预期：类型错误，String 不能赋给 `Ref<Goods>`。

## 9. 第一轮诊断要求

每条诊断至少包含：

- 稳定错误码；
- 错误阶段；
- 中文可读消息；
- 文件和起止位置；
- 主要错误位置；
- 相关声明位置；
- 可选修复提示。

第一批稳定错误码：

```text
SIR-PARSE-001  非法语法
SIR-SYMBOL-001 重复定义
SIR-SYMBOL-002 未定义符号
SIR-TYPE-001   类型不匹配
SIR-TYPE-002   非法 Ref 目标
SIR-TYPE-003   非法 Optional
SIR-FLOW-001   未定义局部变量
SIR-FLOW-002   缺少 Return
SIR-FLOW-003   未声明 Error
SIR-FLOW-004   readonly/query 包含写步骤
SIR-VALID-001  冲突 requirement
SIR-TARGET-001 不支持的 Target 组合
```

## 10. 第一轮验收测试

完成语言设计与后续 Parser 实现时必须满足：

1. 完整合法示例成功解析；
2. 每种声明都有最小合法样例；
3. 第 8 节全部负例在规定阶段失败；
4. 前向引用合法，例如 Goods 可以在 User 后或前声明；
5. 同一名称重复声明能同时指出两处位置；
6. `Optional<T>` 是唯一可空表达；
7. DSL 中不存在 Controller、Service、Mapper、JPA、MyBatis-Plus 注解或调用；
8. Workflow 不允许嵌入未知函数或 Java 表达式；
9. 相同文档构建的 AST 字段和 Source Span 稳定；
10. Redis 关键字在 Core Grammar 中被拒绝，直到对应 Extension 规范被启用。

## 11. 本轮之后的实现顺序

本规范确认后，下一轮工程任务依次为：

1. 将第 3 至第 6 节转成 ANTLR4 Grammar；
2. 定义 Java 21 AST record 和 SourceSpan；
3. 实现 Parse API 与结构化诊断；
4. 把第 7、8、10 节转成自动化测试；
5. Parser 验收通过后，再设计 Semantic Model 和 Symbol Table。

不得在 Parser 阶段提前生成 Java 代码，也不得为了快速演示跳过负面测试。
