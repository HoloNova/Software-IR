# SIR v0.1 Parser 与 AST 第二轮实现报告

日期：2026-07-13  
状态：实现与验收完成，等待进入 Semantic Model 轮次

## 1. 本轮交付

`sir-parser` 模块已经实现：

- ANTLR4 生成的 SIR v0.1 Lexer/Parser；
- `SirParser`、`SirSource`、`ParseResult` 和结构化 Diagnostic API；
- Java 21 sealed interface + record 组成的不可变 AST；
- Unicode code point SourceSpan、逻辑 SourceId 和确定性 AstNodeId；
- AST Builder、字符串解码、版本与 Target 兼容性检查；
- 正例、词法负例、语法边界、AST 不变量和 Workflow Step 形状测试。

## 2. 审查后修正的设计缺口

工程实现前后通过独立审查和失败测试修正了以下问题：

1. `input`、`actor` 是保留变量但原 Grammar 不允许其作为表达式根节点；
2. `0.01` 的尾部会被旧 `INT` 规则错误切分；点数字现为原子 Token，禁止 `0 . 01` 等等价写法；
3. 零参数 Constraint 原先同时接受 `notBlank` 与 `notBlank()`；现只接受前者；
4. `Unit` 原先没有可返回的值；现冻结唯一形式 `return unit;`，并使用 `AstUnitLiteral`；
5. 旧块注释负例规则会吞掉合法闭合注释后的全部文本；现已区分闭合与未闭合注释。
6. AstNodeId 序号原先受系统 Locale 影响；现固定使用 ASCII 数字；
7. Constraint 负数与普通表达式原先生成不同 AST；现统一为 `AstUnaryExpression(NEGATE, literal)`；
8. 缺失 Token 与单独 CR 的诊断位置原先可能漂移；现已与 Lexer 的 LF/CRLF 契约对齐。

## 3. 明确边界

本轮 Parser 只判断文本能否形成合法的 v0.1 语法结构，并执行不依赖符号表的 Header 兼容性检查。

以下内容仍属于后续轮次：

- 全局/局部符号解析和公共知识上下文；
- 类型检查、Constraint Pack 与 Workflow 语义验证；
- Core Semantic IR、Project Symbol Graph 和增量修改；
- Extension、Target Lowering、Lowered IR 和 Generator；
- Spring Boot、MyBatis-Plus、Redis、算法或前端联调实现。

因此，当前通过 Parser 不代表业务语义正确，也不代表能够生成工程代码。
