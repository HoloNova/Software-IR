# SIR v0.1 Lowering 与最小 Spring Boot Target 设计

状态：本轮实现基线  
日期：2026-07-16  
输入基线：`NormalizedSemanticModel`  
范围：`sir-lowering-api`、独立 Spring Boot Lowered IR、最小 Spring Boot Target Lowering

## 1. 目标与非目标

本阶段建立第一条可独立验收的后端管线：

```text
NormalizedSemanticModel
  -> TargetLowering
  -> LoweringAnalysis.Success / Failure
  -> 独立、不可变、可验证的 SpringBootLoweredModel
```

Lowering 只接收 `NormalizedSemanticModel`，不接收 `AstDocument`、`AstSoftware` 或其他 AST 根节点。名称解析已经在 Resolve 阶段完成；Lowering 只使用 Normalized 节点携带的 `SymbolId` 和 `SymbolTable.byId`，禁止调用 `byName` 或根据字符串重新寻找声明。

本轮不生成 Java 文件，不实现模板、完整 Generator、Redis、前端、算法、Change SIR、Project Symbol Graph 持久化或 Java 反向解析。

## 2. 输入充分性审核

当前 `NormalizedSemanticModel` 对本轮是充分的：

- declarations 提供 Enum、Entity、Input、Error、Capability、Workflow、Step 和 Expression 的 canonical 形态；
- 类型中的 `DeclaredType.symbolId`、`RefType.entityId` 和各 Normalized 引用提供稳定语义身份；
- SymbolTable 可按 SymbolId 取得 actor、input 和局部变量的名字与类型；
- SourceSpan、AstNodeId 和 SymbolId 支持 Lowering 诊断与来源追踪；
- metadata/target 提供 namespace 和当前冻结的目标组合。

已知技术债是 `NormalizedSemanticModel.metadata/target` 仍使用 parser 模块的不可变值对象。Lowering 本轮只把它们作为 Normalized Model 的已验证属性读取，不遍历 AST，也不改变 Core API。未来若要让 canonical model 完全脱离 parser 类型，可单独版本化为 `NormalizedMetadata` 与 `NormalizedTarget`；这不是本轮闭环的前置条件。

## 3. 模块边界

### 3.1 sir-lowering-api

只依赖 `sir-semantic`，定义所有 Target 共用的边界：

- `TargetLowering<M>`：`NormalizedSemanticModel -> LoweringAnalysis<M>`；
- `LoweringAnalysis`：结构化 Success/Failure，Failure 至少包含一条 ERROR；
- `LoweringDiagnostic`：错误码、严重级别、消息、SourceSpan、可选 SymbolId/AstNodeId；
- `LoweredModel`：Lowered IR 版本、Target ID、软件名；
- `LoweredNodeId`：Lowered 节点稳定身份；
- `LoweredOrigin`：SourceSpan、AstNodeId、可选 owner SymbolId；
- `LoweredIrValidator<M>`：独立验证已经构造出的 Lowered IR。

该模块不包含 Spring、MyBatis-Plus、HTTP、Java 注解或文件路径。

### 3.2 sir-lowering-spring-boot

依赖 `sir-lowering-api`，包含：

- 冻结的 `SpringBootTargetProfile`；
- Spring/Java/MyBatis-Plus 绑定后的强类型 Lowered IR；
- `SpringBootTargetLowering`；
- 输入边界检查、确定性命名、类型转换和交叉引用验证。

该模块不依赖 Spring Boot 运行库。Spring 只作为目标模型语义存在，不在本阶段编译或运行生成后的应用。

## 4. Spring Boot Target Profile v0.1

唯一接受的目标组合是：

- Java 21；
- Spring Boot；
- MyBatis-Plus persistence；
- MySQL；
- Maven；
- REST interface。

Profile ID 固定为 `spring-boot-java21-mybatis-plus-mysql-rest-v0.1`，Spring Boot 固定为 `3.5.3`，MyBatis-Plus 固定为 `3.5.12`。这些版本是本 Target Profile 的可重复输入，不表示“当前最新版本”。未来 Generator 可直接渲染这些值；本阶段不下载这些依赖。

Target 不匹配时返回 `SIR-LOWER-TARGET-001`，不得静默改成相近技术栈。

## 5. Lowered IR 节点

### 5.1 根节点

`SpringBootLoweredModel` 包含：

- Lowered IR 版本与 Target Profile；
- softwareName、displayName、basePackage；
- 按 SIR 声明顺序保存的 `SpringBootDeclaration`；
- 按声明顺序和固定 role 顺序保存的 `SpringArtifact` ownership 计划。

### 5.2 声明节点

- `LoweredEnum`：Java enum 名、成员及每个成员的来源身份；
- `LoweredEntity`：Java 类型名、表名、identity、字段和持久化形态；
- `LoweredInput`：请求 DTO 名、字段和验证约束；
- `LoweredError`：异常类型名和确定的 HTTP 状态；
- `LoweredCapability`：Controller/Service 名、REST method/path、认证/事务/只读策略、输入输出、失败集合与 Lowered Workflow。

### 5.3 Workflow 与 Expression

Lowered Workflow 对 v0.1 的 7 种步骤逐一建模：Validate、Load、Find、Create、Update、Persist、Return。表达式对 10 种 canonical expression 逐一建模：Boolean、Integer、Decimal、String、Unit、Now、Name、Member、Unary、Binary。

步骤、binding 和 expression 保留已经解析好的 SymbolId；不保存需要再次解析的名称引用。Generator 以后只把这些已绑定节点渲染成固定代码形态。

### 5.4 Java 类型

`LoweredJavaType` 是强类型 sealed 模型：

- Scalar：Boolean、Integer、Long、BigDecimal、String、UUID、LocalDate、Instant、Void；
- Declared：Enum、Entity、Input，携带目标 SymbolId 与 Java 类型名；
- Optional、List：递归包含 element type；
- EntityReference：携带 Entity SymbolId、Java 类型名和 identity 的存储 Java 类型。

EntityReference 显式固定“逻辑引用 + identity 存储形态”，持久化 `Ref<User> seller` 的 Java 属性固定为 `sellerId`、列名固定为 `seller_id`，Workflow binding/member 也直接引用 `sellerId`。未来 Generator 不需要再猜测外键表示或重命名。

## 6. Artifact ownership

本轮不产生文件路径，但提前冻结逻辑 Artifact ownership：

- Enum -> ENUM；
- Entity -> ENTITY_MODEL、MAPPER；
- Input -> REQUEST_DTO；
- Error -> EXCEPTION；
- Capability -> SERVICE、CONTROLLER。

每个 Artifact 有稳定 LoweredNodeId、owner SymbolId、package、simpleName 和 role。LoweredNodeId 只由 Target ID、owner SymbolId 和固定 role 计算，不使用时间、随机数、Locale 或遍历序号。未来 Generator 只能渲染 ownership 列表中的 Artifact。

## 7. 不变量与验证

所有 record 构造时做 null/blank 检查和集合防御复制。跨节点验证由 `SpringBootLoweredIrValidator` 返回结构化诊断：

1. LoweredNodeId、声明 SymbolId、Artifact qualified name 不重复；
2. 声明与 Artifact 顺序稳定；
3. 所有 Declared/EntityReference、fails、step、binding 和 expression SymbolId 都能按 ID 指向正确种类的声明或变量；
4. 不允许 `sir://unknown`；
5. basePackage 和所有 Java 名称合法；
6. Capability 恰有一个末尾 Return；
7. command/query、atomic/readonly 与 HTTP/事务策略一致；
8. EntityReference 必须能找到目标 Entity identity 类型；
9. ownership 完整且无多 owner；
10. 公开集合不可修改。

Lowering 先验证输入可支持性，再构造 IR，最后运行 IR Validator。任一阶段存在 ERROR 都返回 Failure，不暴露半可信 Lowered Model。

## 8. 确定性映射

- 声明、字段、步骤、binding 和 expression 保持 Normalized Model 顺序；
- fails 保持 Normalized Model 已规范化的 SymbolId 顺序；
- Artifact role 使用固定枚举顺序；
- Java 类型名使用已经验证的声明名，不做 Locale 相关大小写转换；
- REST path、表名和列名使用显式 `Locale.ROOT` 的 kebab/snake 算法；
- 相同输入重复 Lowering，以及切换默认 Locale 后 Lowering，必须得到相等结果。

## 9. 当前支持与明确拒绝

支持校园二手交易示例及当前 v0.1 canonical 子集：Enum、persistent Entity、generated auto/uuid identity、Input、Error、Capability、全部 7 种 Workflow step、全部 10 种 canonical expression、五种 Constraint、authenticated/atomic/readonly、command/query、Unit/Optional/List/Ref 类型。

明确拒绝：

- 非冻结 Target 组合；
- 非持久化 Entity 或无法映射的 identity/type；
- 未绑定、缺失或种类错误的 SymbolId；
- 未知 Constraint、Requirement、Step、Expression 或类型；
- 非法 Java namespace/name；
- 带 ERROR 的 Normalized Model；
- Redis/缓存、前端、算法、Extension、分支循环、任意 Java 源码和文件渲染。

## 10. 诊断

Lowering 使用独立错误码域：

- `SIR-LOWER-INPUT-001`：输入快照不可信或结构损坏；
- `SIR-LOWER-TARGET-001`：Target Profile 不支持；
- `SIR-LOWER-BINDING-001`：SymbolId 缺失、unknown 或种类错误；
- `SIR-LOWER-TYPE-001`：类型无法映射；
- `SIR-LOWER-FEATURE-001`：当前 Target 不支持的语义；
- `SIR-LOWER-NAME-001`：目标名称非法；
- `SIR-LOWER-IR-001`：Lowered IR 不变量失败。

诊断按 SourceSpan 起点、错误码、消息稳定排序并去重。

## 11. 测试与验收

先写失败测试覆盖错误 Target、未知 SymbolId、错误 Symbol kind、非法 namespace、未知 Constraint、带错误诊断的输入和损坏 Lowered IR；再实现 Lowering。

正面测试覆盖校园二手交易完整模型、全部 Workflow step、类型/约束映射、Artifact ownership、不可变集合、同输入重复运行、Locale 切换和独立 Validator。最终运行父工程离线 `clean verify`，并统计各模块实际测试数。
