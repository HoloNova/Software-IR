# SIR v0.1 阶段讨论提炼

> 本文只保存结论与演进脉络，不保存原始对话。

## 讨论起点

项目首先确认：Software IR 的价值不是替代 Java 语法，也不是生成 CRUD 模板，而是把模型生成前后的依赖、类型、变量、符号、作用域、组件选择和架构规则放入可检查的公共黑板，尽量保证同一元素只有一种语义表达。

## 确定性生成的边界

讨论否定了两个极端：一是 SIR 后完全由模型自由补齐工程，二是让 SIR 逐行描述全部 Java。当前选择是：SIR/Normalized Model 固化核心语义，Target Profile 与 Lowering 固化技术分支，Generator 只渲染；模型可负责生成/修改 SIR 和处理受契约约束的扩展任务，但不能绕过语义校验。

## 组件和分支

Spring Boot + MyBatis-Plus 可以成为确定的 Target，但不能进入 Core。Redis 虽然依赖接入简单，语义上还涉及 TTL、序列化、一致性和失败策略，因此推迟为 Extension + Resource/Capability + Target Lowering。依赖版本应由 Target Profile 冻结，后续可生成 Maven 文件、拉取脚本或使用指南，但必须有可验证的失败路径。

## 可维护与修改

项目修改不能靠“重新抽取整份 SIR，再覆盖生成整个工程”。未来 Change SIR 应以 SymbolId/AstNodeId 精确定位，并依赖 Project Symbol Graph、增量 Pass、Artifact ownership 和用户代码保护区只更新受影响产物。当前稳定身份和一次绑定是这条路线的地基。

## 三轮工程结果

- 第一阶段建立 v0.1 Grammar、Parser、AST 和最小语言规范。
- Semantic 阶段建立 Resolve、Type、Validate、Normalize、SymbolTable、类型系统和 canonical model。
- 第三轮审查发现并修复顺序作用域、引用绑定、重复 SymbolId、Create/Update/Persist、类型位置、Return、Constraint、真正 Normalize、确定性和职责边界问题。
- 最终复核进一步修复未知 Find 异常、完整 AstNameRef 身份、Normalize 重解析、负数/Decimal Constraint、诊断归属与链式成员访问。
- 最终基线在提交 `4981ce4`，clean verify 119 项测试通过。

## 下一阶段共识

新会话从独立 Lowered IR 与 `sir-lowering-api` 的规范开始，然后实现最小 Spring Boot Target Lowering。代码生成必须晚于 Lowered IR 验证；Redis、算法、前端联调和 Change SIR 不与第一版 Lowering 同时展开。
